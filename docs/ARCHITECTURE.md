# 架构与实测

## 运行结构

一个 Go 二进制，使用 `net/http` 路由并内嵌 Vue 构建产物；一份 SQLite 数据库，无 Redis、消息代理、ORM 或额外服务。直接 Go 依赖仅 `modernc.org/sqlite`。前端运行依赖为 Vue 和 Lucide 图标，管理后台独立加载。

数据库分读写连接池：一个写连接、最多八个读连接，WAL、5 秒 busy timeout、每连接 2 MiB 页缓存。写事务使用 IMMEDIATE 锁，读写之间的成员上限、好友关系、最后一位管理员等不变量在同一个数据库事务内检查。消息索引为 `(room_id, id)`，历史按消息 ID 游标分页。

消息先写入并提交，再向在线成员发送 SSE 事件；HTTP POST 确认携带持久化后的消息 ID。`(sender, client_id)` 唯一约束处理重复发送。事务中读取当时的成员名单，推送不占用数据库事务。

每个 SSE 连接一个容量 32 的队列；慢客户端队列满即断开，不阻塞其他收件人。每 20 秒心跳并复查会话，单次写入有 10 秒截止时间。退出或停用账号会主动关闭该账号连接。前端指数退避重连，并重新读取会话列表和最新 50 条消息；SSE 本身不作为持久化事件日志，不保证重放每个历史事件。

数据库事务与事件广播之间发生进程退出时，已提交消息仍保留，客户端重连后从数据库恢复。正常推送期间消息按 ID 去重并排序，切换会话时忽略旧请求结果。前端浏览历史或切换到后台时不会把不可见消息标记为已读。

## 账号与权限

- 首次管理员必须提交启动令牌；初始化检查和账号写入在同一事务中。
- 密码使用独立随机盐、PBKDF2-HMAC-SHA256，210,000 次迭代。最多 4 个并行密码计算任务；登录/注册另有 IP 限流。
- 会话令牌为 256 位随机值，只在 HttpOnly / SameSite=Strict cookie 中保存；数据库仅保存 SHA256 摘要，7 天过期。改密撤销全部旧会话。
- 写请求校验 Origin 和 Fetch Metadata；POST/PATCH 要求 JSON；请求体不超过 16 KiB；文字消息不超过 8 KiB。
- REST 接口独立检查用户和成员/管理员权限；前端隐藏按钮不作为权限边界。
- 管理员无权通过成员接口读取未加入群聊的消息。管理后台只展示群聊元数据，且不列出私聊内容。
- 用户文本通过 Vue 插值显示，不解析 HTML。CSP 限制脚本和网络为同源。
- API 每用户突发 30 次写请求、持续 5 次/秒；用户搜索突发 20、持续 2 次/秒。限流键数量受限，不无限增长。

## 2026-09-10 本机测量

Windows amd64，Intel Core i9-12900H，Go 1.27.0，20 个逻辑 CPU。以下是开发机短时测试，不代表生产 SLA 或长期稳定性。

| 项目 | 结果 |
| --- | --- |
| Windows 单程序大小（去除调试符号） | 11,603,456 B，约 11.07 MiB |
| 聊天首屏 HTML + JS + CSS | 约 130.8 kB，未启用传输压缩 |
| 管理后台额外 JS | 8.72 kB，按需加载 |
| 独立服务空闲工作集 / 私有提交内存 | 13.39 / 49.88 MiB |
| 同时在线 SSE 连接 | 1,000 |
| 组织方式 | 10 个群，每群 100 个连接 |
| 持久化发送 | 100 条 |
| 实际接收推送 | 10,000 次 |
| 写入窗口 | 325.39 ms |
| 写入速率 | 307.3 条/秒 |
| HTTP POST p50 / p95 / p99 | 146.37 / 229.23 / 229.81 ms |
| 测试进程连接前 / 连接后 Go 堆 | 0.58 / 37.10 MiB |
| 每连接增量堆 | 37.40 KiB |
| 慢连接丢弃 | 0 |
| 内存中向 100 个收件人广播 | 7.57 µs/op，120 B/op，6 allocations/op |

空闲内存来自独立发布程序启动后、未创建用户时的 Windows `WorkingSet64` 和 `PrivateMemorySize64`；二者是不同指标，不可相加。首屏大小不含 favicon、HTTP 头或网络层开销。

界面动效沿用 OA 的 `cubic-bezier(0.2, 0, 0, 1)`：侧栏 340ms 负边距过渡、页面 240ms 切换、消息 340ms 入场。动效只在交互时触发，无常驻动画循环；系统要求减少动态效果时关闭。加入 Vue 过渡支持后，首屏由约 119.1 kB 增至 130.8 kB；上表内存与连接数据仍为加入动效前的后端测量。

连接测量来自 `TestLoad1000Connections`。客户端与服务端同进程，因此堆内存同时包含两端，不是单独服务端 RSS。100 条消息以最多 50 个并行请求发送，写入延迟包含 SQLite 排队时间。广播微基准排除了网络和数据库成本，不能用它推算完整服务吞吐。

可复用测试和测量命令见 README。应在目标机器上测试实际消息大小、群人数和持续写入，再确定实例容量。需要多实例或显著更高持续写吞吐时，应另行实现共享持久化和跨实例事件投递；当前实现未声称具备这些能力。
